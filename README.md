# 酿见 AI · 中小酒企的场景化营销智能体

> 2026 多彩贵州·贵客松 | 传统行业 AI 解决方案 | AI × 白酒

一句话：**先看见消费者和生活场景，再决定这瓶酒怎么卖。**

## 为什么做它

中小酒企真正缺的往往不只是一篇文案，而是一套面向消费者的营销能力：

- 过去依赖宴席、团购、礼赠和渠道，面对消费者直连时不知道先经营哪类人群；
- 会讲工艺、年份、产区，却不一定知道这瓶酒应该进入消费者的哪张餐桌；
- 市场团队小，公众号、朋友圈、短视频等渠道难以持续运营；
- 内容发布前缺少事实核验与风险检查，容易出现未经证实的工艺、资质、物流、售后等承诺。

**酿见 AI** 不把“目标人群是谁、消费场景是什么”全部交给用户自己回答，而是先从产品底层信息出发，给出消费者与场景诊断，再进入内容执行。

名称里的“酿”对应酒行业，“见”对应营销的第一步：**看见消费者、场景和机会。**

## 核心链路

```text
一厂一档
   ↓
产品底层信息
   ↓
营销诊断
   ├─ 优先消费者
   ├─ 场景机会
   └─ 渠道建议
   ↓
公众号 / 朋友圈 / 短视频
   ↓
品牌事实核验
   ↓
酒类营销风险检查
   ↓
评论区与私域承接
```

## 1. 一厂一档

每家酒厂维护自己的品牌档案：

- 产品与价格带
- 品牌定位和语气红线
- 已知消费者与真实消费场景
- 酒厂人物、车间、餐桌等真实素材
- 工艺、产区、规格、资质等品牌事实证据

同一套 Agent 在不同酒厂上使用时，不依赖一份通用“白酒提示词”。

## 2. 先诊断，再写内容

即使用户不知道“目标人群是谁”“典型场景是什么”，也可以先只提供产品、价格带、产区和已有卖点。

规则版 MVP 会先输出：

- 消费者分群与优先级
- 人群的购买需求与触发时机
- 值得测试的生活场景
- 对应内容角度与转化动作
- 渠道建议与下一步测试计划

当前规则版主要按价格带和企业已知信息做判断；正式版可接入行业知识库、真实销售数据和 LLM。

## 3. 引导式营销工作台

前端不再用一张长表单要求用户一次填完，而是拆成三步：

1. **产品底子**：产品名、价格、已确认卖点、产区；
2. **营销线索**：目标人群、真实场景、营销目标、已有渠道——全部允许不知道；
3. **品牌证据**：品牌语气、表达红线、事实证据、真实故事素材。

不知道的字段可以直接跳过，让 Agent 先做判断。结果区按“策略诊断 / 内容资产 / 发布检查”三个视图呈现，减少第一次使用的理解成本。

界面设计参考了成熟 AI 营销工具的交互原则，而不是直接复制视觉：

- Jasper Canvas：把营销工作放进统一工作空间，项目上下文与内容资产持续共享；
- HubSpot Breeze：先理解当前业务上下文，再给出下一步动作，而不是只返回一段聊天答案；
- Copy.ai Workflows：把复杂营销过程显性化成多步骤工作流，降低非专业用户理解成本。

酿见的前端因此采用“引导输入 + 可视化 Agent 流程 + 分层结果视图”的结构，而不是传统后台表格或一页式宣传页。

## 4. 内容三件套

在营销判断之后，再生成：

- 公众号：品牌事实、真实故事与场景解释
- 朋友圈：熟人信任和具体场景表达
- 短视频：真实人物、餐桌、产区和产品静物脚本

目标不是把白酒只写成商务应酬用品，而是持续发现成年消费者真实存在的聚餐、佐餐、朋友见面、礼赠、品鉴等多元场景。

## 5. 事实证据优先

正式营销内容中，不允许 Agent 为品牌自动补齐未经确认的事实。

例如：

- 是否自有窖池
- 是否大曲坤沙
- 是否有溯源码
- 是否有官方商城
- 是否包邮
- 是否支持退换

没有资料支持时，系统应提示补充，而不是替企业编一个答案。

工作台支持按“标签｜事实｜来源”录入事实证据，例如：

```text
度数｜42%vol｜瓶身标签
工艺｜大曲坤沙｜企业产品资料
```

## 6. 发布前检查

生成内容会继续进入两层检查：

1. **品牌事实检查**：卖点是否绑定企业提供的事实证据；
2. **酒类营销风险检查**：检测诱导饮酒、将饮酒与情绪/功能效果绑定、绝对化宣传等高风险表达。

规则版检查只作为风险提示，不替代企业正式法务审核。

## 7. 评论区承接

针对价格、真假、购买渠道、礼赠等高频问题生成回复建议。

原则同样是：**有资料再回答，没有确认就不替品牌承诺。**

## 当前版本边界

- 后端：Python FastAPI + Pydantic
- 前端：React 18 + Vite + TypeScript
- 当前营销诊断、内容生成与风险检查以规则引擎为主，保证演示稳定
- 已预留 LLM、行业知识库、品牌事实库和历史经营数据的后续升级空间
- “酿见 AI”为当前产品工作名，正式商业使用前仍应进行完整商标检索

## 下一阶段

优先找真实中小酒企验证：

1. 企业是否愿意完成一次品牌/产品事实建档；
2. Agent 给出的人群 × 场景建议是否比“直接生成文案”更有价值；
3. 连续测试 2-4 周后，哪些场景真正带来咨询、成交和复购；
4. 用真实反馈反向调整下一轮营销建议。
