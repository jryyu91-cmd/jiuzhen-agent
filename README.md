## 为什么做它

中小酒企真正缺的往往不只是一篇文案，而是一套面向消费者的营销能力：

- 过去依赖宴席、团购、礼赠和渠道，面对消费者直连时不知道先经营哪类人群；
- 会讲工艺、年份、产区，却不一定知道这瓶酒应该进入消费者的哪张餐桌；
- 市场团队小，公众号、朋友圈、短视频等渠道难以持续运营；
- 内容发布前缺少事实核验与风险检查，容易出现未经证实的工艺、资质、物流、售后等承诺。

**酿见 AI** 不把“目标人群是谁、消费场景是什么”全部交给用户自己回答，而是先从产品底层信息出发，给出消费者与场景诊断，再进入内容执行。

名称里的“酿”对应酒行业，“见”对应营销的第一步：**看见消费者、场景和机会。**

## 核心链路

```text
一厂一档
   ↓
产品底层信息
   ↓
营销诊断
   ├─ 优先消费者
   ├─ 场景机会
   └─ 渠道建议
   ↓

   ↓

   ↓
酒类营销风险检查
   ↓
评论区与私域承接
```

## 1. 一厂一档

每家酒厂维护自己的品牌档案：

- 产品与价格带
- 品牌定位和语气红线
- 已知消费者与真实消费场景
- 酒厂人物、车间、餐桌等真实素材
- 工艺、产区、规格、资质等品牌事实证据

同一套 Agent 在不同酒厂上使用时，不依赖一份通用“白酒提示词”。

## 2. 先诊断，再写内容

即使用户不知道“目标人群是谁”“典型场景是什么”，也可以先只提供产品、价格带、产区和已有卖点。

规则版 MVP 会先输出：

- 消费者分群与优先级
- 人群的购买需求与触发时机
- 值得测试的生活场景
- 对应内容角度与转化动作
- 渠道建议与下一步测试计划

当前规则版主要按价格带和企业已知信息做判断；正式版可接入行业知识库、真实销售数据和 LLM。

## 3. 引导式营销工作台

前端不再用一张长表单要求用户一次填完，而是拆成三步：

1. **产品底子**：产品名、价格、已确认卖点、产区；
2. **营销线索**：目标人群、真实场景、营销目标、已有渠道——全部允许不知道；
3. **品牌证据**：品牌语气、表达红线、事实证据、真实故事素材。

不知道的字段可以直接跳过，让 Agent 先做判断。结果区按“策略诊断 / 内容资产 / 发布检查”三个视图呈现，减少第一次使用的理解成本。

界面设计参考成熟 AI 营销工具的交互原则，而不是直接复制视觉：

- Jasper Canvas：统一工作空间；
- HubSpot Breeze：结合业务上下文给出下一步动作；
- Copy.ai Workflows：把复杂营销过程显性化成多步骤工作流。

## 4. 内容资产

在营销判断之后，再生成：

- 公众号：从一个具体生活片段切入，再自然带到产品；
- 朋友圈：像熟人随手分享，短句、停顿、留白更多；
- 短视频：用餐桌、朋友、产品静物和可核验细节完成 30 秒场景脚本。

**策略层和内容层严格分开。**

“目标人群、场景机会、营销判断、下一步策略”只出现在策略诊断里，不直接塞进消费者看到的成品文案。

规则版内容遵循这些基础纪律：

- 少用“消费者、品牌心智、营销机会、策略”等内部词；
- 不把一篇内容写成方法论说明书；
- 先写一个看得见的生活片段，再带产品；
- 句子允许有停顿、长短变化和留白，不追求过度工整；
- 不凭空补写品牌亲历、用户评价、工艺、年份或资质；
- 不展示饮酒动作，不把饮酒与解压、消愁、功能效果绑定。

Demo 的目标不是证明规则模板能替代专业创作者，而是让评委直观看到：**同一套营销判断，可以被转译成不同渠道的消费者内容。**

## 5. 事实证据优先

正式营销内容中，不允许 Agent 为品牌自动补齐未经确认的事实。

例如：

- 是否自有窖池
- 是否大曲坤沙
- 是否有溯源码
- 是否有官方商城
- 是否包邮
- 是否支持退换

没有资料支持时，系统应提示补充，而不是替企业编一个答案。

工作台支持按“标签｜事实｜来源”录入事实证据，例如：

```text
度数｜42%vol｜瓶身标签
工艺｜大曲坤沙｜企业产品资料
```

## 6. 发布前检查

生成内容会继续进入两层检查：

1. **品牌事实检查**：卖点是否绑定企业提供的事实证据；
2. **酒类营销风险检查**：检测诱导饮酒、将饮酒与情绪/功能效果绑定、绝对化宣传等高风险表达。

规则版检查只作为风险提示，不替代企业正式法务审核。

## 7. 评论区承接

针对价格、真假、购买渠道、礼赠等高频问题生成回复建议。

原则同样是：**有资料再回答，没有确认就不替品牌承诺。**

## 8. 在线部署

仓库根目录提供单服务部署文件：

- `Dockerfile`：一次构建 React 前端 + FastAPI 后端；
- `render.yaml`：Render Blueprint；
- `/api/health`：健康检查。

这样比赛评审不需要在本地安装 Python、Node.js 或 Docker，只需要打开公开链接。

详细步骤见：[`docs/评委快速体验.md`](docs/评委快速体验.md)

## 本地运行

### Mac / Linux

```bash
git clone https://github.com/jryyu91-cmd/jiuzhen-agent.git
cd jiuzhen-agent
zsh setup.sh
```

浏览器打开 `http://localhost:5173`。

### Docker

```bash
git clone https://github.com/jryyu91-cmd/jiuzhen-agent.git
cd jiuzhen-agent
docker compose up --build
```

## 当前版本边界

- 后端：Python FastAPI + Pydantic
- 前端：React 18 + Vite + TypeScript
- 当前营销诊断、内容生成与风险检查以规则引擎为主，保证演示稳定
- 已预留 LLM、行业知识库、品牌事实库和历史经营数据的后续升级空间
- “酿见 AI”为当前产品工作名，正式商业使用前仍应进行完整商标检索
