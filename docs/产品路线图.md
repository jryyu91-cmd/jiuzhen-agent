# 酿见 AI · 产品路线图

这份路线图按“真实中小酒企长期使用”设计，比赛 Demo 只是第一阶段验证，不反过来限制产品形态。

## 一、产品目标

酿见不要求用户先学 AI，也不要求用户先成为营销专家。

长期目标是：

> 企业把已有资料和日常问题交进来，酿见把散落的信息变成可复用营销资产，并持续帮助它判断“卖给谁、什么场景、怎么说、什么不能说、下一步做什么”。

衡量产品好不好，不先看功能数量，而看：

- 用户少整理一步了吗；
- 同一份资料少重复录入了吗；
- 一个事实还能找到来源吗；
- 一个建议能小范围验证吗；
- 用过一段时间以后，酿见是不是比第一次更懂这家酒厂。

## 二、核心系统

### 1. 多入口资料接入

真实企业资料来源不是一张标准表单。

未来逐步支持：

- Web 上传 PDF / Word / Excel / 图片；
- 小程序拍瓶身、包装、证书、门店物料；
- 微信 / 企业微信转发文件、文字、语音；
- 历史公众号 / 视频文案导入；
- 企业网盘 / 知识库；
- ERP / CRM / 订单与门店数据（PoC 后期再接）。

原则：**入口可以很多，后面共用同一个品牌与营销记忆。**

### 2. 品牌事实层

所有硬事实尽量保存：

- `value`：事实是什么；
- `source`：来自哪个文件/系统/人工确认；
- `source_excerpt`：支持它的原文；
- `status`：已确认 / 待确认 / 已失效；
- `updated_at`：最后更新时间。

事实层不能混入“建议”。

例如：

- `42%vol` 可以是事实；
- `适合年轻人` 不是事实，是营销推断；
- `朋友小聚是高潜场景` 也不是事实，除非以后有经营数据支持。

### 3. 一厂一档营销记忆

未来数据库按企业隔离，逐步积累：

- 企业事实；
- SKU 事实；
- 品牌语气与表达红线；
- 历史内容；
- 已测试人群与场景；
- 常见客户问题；
- 营销活动；
- 咨询、到店、成交、复购等反馈。

目标是“一次确认，后面复用”。

### 4. 营销诊断 Agent

不是输出永久定位，而是给“下一轮值得验证的假设”。

输入包括：

- 已确认品牌 / SKU 事实；
- 当前营销目标；
- 已有渠道；
- 企业已知客群与场景；
- 历史营销表现（后续）；
- 季节 / 节庆 / 本地活动等业务上下文（后续）。

输出包括：

- 优先成年消费者；
- 场景机会；
- 为什么这样判断；
- 哪些是事实、哪些是推断；
- 怎么低成本测试；
- 用什么指标决定继续 / 停止 / 调整。

### 5. 内容执行层

策略确认后，再生成不同渠道资产。

内容不应该重复解释后台营销策略，而应该直接面向消费者。

未来可以扩展：

- 公众号；
- 朋友圈；
- 小红书；
- 短视频脚本 / 分镜；
- 直播话术；
- 门店海报 / 活动物料；
- 经销商朋友圈物料；
- 私域跟进话术。

扩渠道不是第一优先级；先保证事实、场景和品牌语气一致。

### 6. 发布前安全闸

至少包含：

- 品牌事实校验；
- 酒类广告基础规则；
- 平台规则；
- 企业自己的禁用词 / 禁用承诺；
- 购买链接、库存、物流、售后等实时事实检查（接系统后）。

### 7. 经营反馈闭环

长期壁垒不在“生成更多文案”，而在真实反馈。

每条内容 / 活动逐步回收：

- 曝光；
- 阅读 / 完播；
- 收藏 / 评论；
- 私信 / 咨询；
- 到店 / 下单；
- 客单价；
- 复购；
- 常见异议。

酿见需要逐渐回答：

> “对这家具体酒企来说，过去什么人群 × 场景 × 表达 × 渠道更有效？”

而不是永远依赖一套行业通用模板。

## 三、不同终端怎么分工

### Web 工作台

适合市场负责人：

- 批量资料建档；
- SKU 管理；
- 完整策略诊断；
- 内容审批；
- 活动与数据复盘；
- 团队权限。

### 微信小程序

适合老板、销售、门店：

- 拍一张产品 / 证书；
- 上传一个文件；
- 临时问“这个客户怎么推荐”；
- 一键生成朋友圈；
- 查看品牌允许说的事实；
- 把现场客户问题带回营销大脑。

### 企业微信 / 微信入口

目标是尽量少改变企业已有习惯：

- 转发文件给酿见；
- 转发语音；
- 转发客户问题；
- 收到结构化结果和待确认项。

### App

不作为早期目标。

只有当移动端的使用频率、通知、素材采集、门店协作等场景已经验证，才值得做独立 App。

## 四、阶段路线

### Phase 0 · 当前 Demo

验证主链：

`原始资料 → 事实证据 → 人群/场景 → 内容 → 发布检查`

当前支持：

- PDF 文本版 / 文本资料；
- 事实来源和原文片段；
- 可选 LLM 资料理解；
- 可选 LLM 营销推理；
- 规则兜底；
- 公众号 / 朋友圈 / 短视频；
- 基础合规与评论承接。

### Phase 1 · 真实企业 PoC（1-4 周）

只找 1-3 家中小酒企。

目标：

- 用它们现成资料完成建档；
- 验证第一次建档需要多久；
- 验证企业是否愿意确认事实；
- 每家只跑 2-3 个场景；
- 记录咨询 / 到店 / 成交反馈。

此阶段优先做：

- 正式数据库；
- 企业 / SKU 权限；
- 图片 OCR / 视觉理解；
- 档案版本与事实失效机制；
- 内容历史；
- 基础数据回填。

### Phase 2 · 日常可用（1-3 个月）

目标：从“能演示”变成“市场人员每周会打开”。

优先：

- 小程序轻入口；
- 企业微信 / 微信资料转入；
- 一键复用历史档案；
- 活动任务模板；
- 内容审批与团队协作；
- 常见客户问题沉淀；
- 简单营销复盘。

### Phase 3 · 数据驱动营销大脑

当真实数据足够以后，再做：

- 场景表现排名；
- 人群 × 场景 × SKU 推荐；
- 内容效果归因辅助；
- 经销商 / 门店差异化建议；
- 复购与用户生命周期运营；
- 与 CRM / ERP / 电商 / 即时零售对接。

## 五、功能优先级判断

每个新功能先问四个问题：

1. 它能让酒厂的人少做一步吗？
2. 它会沉淀成长期资产，还是只展示一次 AI 很厉害？
3. 它能利用这家企业独有的数据 / 事实 / 反馈吗？
4. 不做它，用户最核心的工作链还能不能跑通？

如果只是“再多生成一种文案”，优先级通常低于：

- 少填一次资料；
- 找回一个事实来源；
- 避免一次错误承诺；
- 发现一个更值得测试的场景；
- 让真实反馈进入下一轮判断。
