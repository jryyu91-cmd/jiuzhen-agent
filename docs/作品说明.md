# 作品说明 · 酿见 AI

> 多彩贵州·贵客松 | 赛道二 · 传统行业 AI 解决方案 | AI × 白酒

## 0. 为什么是这个题目

酿见 AI 解决的不是“AI 会不会写白酒文案”这个小问题。

中小酒企进入消费者直连阶段后，真正容易卡住的是一整条链：不知道先经营谁，不知道这瓶酒适合进入什么生活场景，不知道不同平台该怎么表达，也缺少持续运营和复盘的人力。

产品因此把能力拆成：

**营销诊断 → 人群/场景 → 内容资产 → 事实核验 → 风险检查 → 评论承接。**

## 1. 作品名 + 一句话

**酿见 AI** —— 先看见消费者和生活场景，再决定这瓶酒怎么卖。

“酿”对应酒行业，“见”对应营销的第一步：看见消费者、场景和机会。

## 2. 谁在用

区域中小酒企的市场负责人、品牌负责人，或者兼顾销售与内容运营的少人团队。

他们往往没有完整的品牌、内容、投放、用户运营团队，但又需要同时面对公众号、朋友圈、短视频等渠道。

## 3. 没有它的时候怎么办

常见状态是：

产品资料不少，但不知道先打哪类消费者；
知道工艺和产区，却不知道怎样把这些信息放进具体生活场景；
临时找同行内容参考，公众号、朋友圈、短视频各写各的；
评论区出现价格、真假、购买渠道、送礼等问题后，再人工逐条处理。

## 4. 酿见做了什么

### 第一步：一厂一档

建立品牌档案，保存：

- 产品和价格带；
- 品牌语气与表达红线；
- 已知消费者和真实消费场景；
- 酒厂人物、车间、餐桌等真实素材；
- 工艺、产区、规格等事实证据。

### 第二步：先做营销诊断

用户不知道目标人群和消费场景也可以开始。

Agent 会先给出：

- 优先消费者；
- 购买需求和触发时机；
- 值得测试的生活场景；
- 内容角度与转化动作；
- 下一步测试建议。

### 第三步：再生成内容资产

输出：

- 公众号；
- 朋友圈；
- 30 秒短视频脚本。

这里有一个重要边界：**策略判断留在策略区，成品内容只面向消费者说话。**

内容从具体生活片段切入，减少营销术语、总结腔和“方法论说明书”式表达；同时不凭空补写亲历、用户评价、工艺、年份、资质等事实。

### 第四步：事实与风险检查

发布前检查：

- 当前卖点是否有企业资料支撑；
- 是否命中诱导饮酒、功能暗示、绝对化宣传等高风险表达。

规则检查只做演示级风险兜底，不替代正式法务审核。

### 第五步：评论承接

针对价格、真假、购买渠道、礼赠等高频问题给出回复建议。

没有企业资料确认的商城、物流、退换、工艺等事实，不替品牌承诺。

## 5. 评委怎么体验

### 推荐：公开 Demo

最终比赛材料优先提供一个公开网页地址。

评委打开页面后，直接点击首页：

**「30 秒一键体验演示」**

无需注册、无需填写表单，即可自动装配演示档案并跑完整链路。

重点查看：

1. 策略诊断；
2. 内容资产；
3. 发布检查；
4. 评论区承接。

详细说明见：`docs/评委快速体验.md`。

### 技术复现

仓库同时保留：

- Docker Compose 本地运行；
- Mac / Linux `setup.sh` 一键启动；
- 根目录单容器 `Dockerfile`，用于部署公开 Demo；
- `render.yaml`，用于 Render Blueprint 部署。

## 6. 技术实现

- 后端：Python FastAPI + Pydantic；
- 前端：React 18 + Vite + TypeScript；
- 当前营销诊断、内容生成与风险检查以规则引擎为主，优先保证 Demo 可解释、稳定、无需外部 API Key；
- 已预留 LLM、行业知识库、品牌事实库、历史经营数据的升级空间。

## 7. 演示数据说明

内置品牌档案均为演示数据，不代表真实酒厂经营事实。

演示数据中使用的工艺、度数、规格、故事素材均显式标记为演示档案或演示素材。

## 8. 再给 100 天，先做什么

第一步不是继续增加更多生成渠道，而是找真实中小酒企做连续验证：

1. 花一周完成品牌事实和产品建档；
2. 用 Agent 选择 2-3 个“人群 × 场景”组合；
3. 连续测试 2-4 周；
4. 回收阅读、互动、咨询、成交等数据；
5. 用真实反馈调整下一轮营销判断。

产品最终希望积累的不是“更多白酒文案模板”，而是这家酒企自己的消费者、场景、事实和经营反馈。
